# 统一记录入口与模块编辑器

## 交互

系统快捷入口统一为「记录」：先截取当前页面，再打开记录编辑页。圈选不再是必经步骤，也不再通过自动读取选中文字来判断记录方式。

编辑页独立提供：

- 我的想法。
- 摘录：可手动输入，或主动读取剪贴板第一条文字。
- 页面原文：可手动填写，或主动尝试读取当前来源页的可访问文字。
- 来源链接及识别到的应用。
- 完整页面截图：最初截取的原图。
- 圈选与批注：从最初原图编辑产生的独立结果。
- 自定义标签及想法／待办类型。

模块勾选仅决定是否加入最终记录，取消勾选不清空本次草稿。页面文字与截图可以同时保留；摘录不要求必须来自剪贴板。未选中的资料不会作为隐藏附件、来源字段或 AI 上下文随记录保存。

为恢复编辑状态，草稿可能暂存在应用私有目录，包含尚未勾选的编辑内容。保存或明确放弃后清理本次草稿；这与正式记录保存、同步及 AI 资料范围分开处理。

「圈选与批注」在本次冻结原图上打开画布，支持圈选、画笔、荧光笔、撤销与整张。确认后回到同一记录页；取消则保留此前已经确认的结果与文字。重新圈选不会再次截屏，也不会覆盖完整页面截图。

截图权限未开启或页面禁止截图时，保留明确说明，并允许选择仅记录文字；不绕过系统安全窗口保护。读取原文和剪贴板均为显式操作，打开记录页不自动读取它们。

「保存并与 AI 聊聊」先提交本机记录，再打开原有记录对话流程，不在记录页自动调用模型。

## 数据兼容

复用现有记录与附件协议，不迁移旧记录：

| 选择的截图模块 | 附件 | 上下文含义 |
| --- | --- | --- |
| 仅完整页面 | `context.png` | `purpose: page_context`，没有圈选位置与虚构的选区附件 |
| 仅圈选批注 | `original.png`、`annotated.png` | 圈选结果；完整页面不保留 |
| 两者都选 | 三份附件 | 完整页面保留真实圈选坐标，批注不修改原图 |
| 两者都不选 | 无图片附件 | 只保存选中的文字、链接等内容 |

Android 的 `hasImage` 继续表示存在圈选附件对，不改为“任何图片”；消费端必须同时考虑 `contextFile`。仅完整截图也算有效内容，支持列表预览、详情、编辑、同步、分享、Markdown 导出与 AI 对话快照。

剪贴板摘录与当前页面的关系不自动宣称已验证；页面原文只代表应用提供的可访问内容，不承诺文章全文。页面读取失败、来源发生变化或超时不覆盖已编辑内容。

## 入口兼容

Android 保留原有受系统权限保护的磁贴组件身份，只在磁贴添加列表中公开一个「记录」入口。旧「随手记」组件转到相同截图优先流程。系统已固定的重复按钮可由用户在快捷设置中移除；若设备不保留旧组件磁贴，在设置 → 快捷方式与权限中重新添加「记录」。

Windows 托盘与主入口显示统一记录操作，旧快捷键继续作为同一流程的兼容入口。

本次模块选择针对新建记录。已有记录继续使用原有文字编辑能力，保留其图片附件，不把取消勾选解释为删除旧附件；没有扩大服务端附件替换协议。

### 标签交互滚动修复（2026-10-08；Android 1.21.1-test）

1.21.0 的记录页在每次布局后都会把仍拥有焦点的输入框滚入屏幕。用户滚动到标签区域后，展开模块或载入已有标签触发布局，而焦点仍可能停在上方的想法输入框，因此页面跳回旧位置。

修复后仅在窗口可用高度缩小时补偿输入光标位置，普通模块展开与标签选择不强制滚动；延迟的焦点任务也会复查输入框是否仍聚焦且可见。

原生布局回归在修复前复现了两处跳动：展开标签的滚动位置从 625 跳到 398，打开已有标签从 751 跳到 386。修复后展开、加载、选择已有标签保持位置，原有键盘缩小视口下的长原文光标可见性测试继续通过。`UnifiedCaptureVisualTest`、`UnifiedCaptureActivityTest`、`TagPickerTest`、`CaptureTagsTest` 共 53 项全部通过，Debug 构建与 lint 通过。自动化结果不替代真机验收。
