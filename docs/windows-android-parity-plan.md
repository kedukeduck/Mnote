# Windows 对齐 Android 1.6.0

实施分支：`agent/windows-android-parity`。Android 基线：`1146e68`。

## 目标与顺序

1. 原生 Windows 账号 / 记录数据层：与 Android 同服务的用户名密码登录、激活、DPAPI 保存会话、账号隔离、离线本地保存、修订号同步和增量拉取、附件哈希校验、离线删除队列。保留旧 Inbox，导入账号必须明确确认。
2. Windows 应用首页：A 主题、应用内列表、全文关键词 / 类型 / 标签过滤、刷新、状态提示；查看和修改想法 / 摘录 / 原文 / 标签，保留截图证据和记录身份，删除确认及同步。
3. 两种全局入口：单次摘录维持截图，先框选 / 批注再填写；随手记独立快捷键，默认不截图、不读剪贴板，可主动读取当前剪贴板文字，独立选择当前应用文字或完整截图上下文。
4. 上下文：截图可额外保留完整虚拟桌面图及圈选坐标；文字 / 截图二选一；不绕过密码、UAC、DRM 等保护，不声称全文一定可得。Windows UI Automation 查询在后台进行、限定目标窗口和读取预算；系统调用可能阻塞，不能冻结主界面。
5. 交付：新增可重复数据和 GUI 回归，保留旧跨端验证，Windows x64 安装包和便携包、签名状态说明、公共下载与哈希校验；不部署线上服务器或写入用户真实账号做测试。

## 数据与安全底线

- 兼容 `schema_version: 1`：`tags`、`evidence.context.text/image`、`source.text`、`comment` 与 Android 相同，未知云端字段保留。
- 上传后端 revision；冲突保留本地修改，不自动覆盖。远端删除不使未同步的本地编辑静默消失。
- URL 校验、禁用重定向、TLS 正常验证；令牌不写入记录、日志或明文配置，密码不持久化。
- 图片和 JSON 写入先暂存后原子发布；下载附件只能请求同源固定角色路径，按大小 / SHA-256 校验。
- 自动同步不在 UI 线程执行，任务绑定账号；切换账号不把旧任务数据写到新账号。

## 初始差距

Windows V1 只有冻结截图、圈选 / 自由笔 / 荧光笔、原始和标记裁剪图、托盘、手填 Token 单向上传，以及打开资源管理器 Inbox。Android 1.6.0 的账号、拉取、真正的应用内资料库、编辑删除、标签、剪贴板随手记和完整上下文均需补齐。
