## 1. 产品定位与目标

### 1.1 用户真正要完成的事

- 在手机 App、电脑应用或网页里看到内容，迅速圈选截图／摘录文字，并写下当时的想法。
- 突然有灵感时快速记录，不被分类、登录、权限弹窗和网络等待打断。
- 无论最初在哪里记录，都能在手机或电脑找到它、续写它、理解当时的上下文。
- 将部分内容转化为可完成的行动；以后回顾行动结果和想法变化。
- 主动选择哪些内容交给 AI，围绕真实记录交流，让 AI 对自己的理解可追溯、可纠正。

核心使用闭环：采集 → 安心保存 → 跨端找回 → 补充思考／形成行动 → 回顾 → 再次记录。

### 1.2 产品原则

| 原则 | 可执行含义 |
| --- | --- |
| 本地优先 | 网络失败不能阻止 Android／Windows 本地采集，不能把已保存说成保存失败 |
| 先记录后整理 | 评论、标题、标签、任务时间都不作为普通截图保存的必填项 |
| 原文与观点分开 | 用户评论、来源原文、OCR、AI 输出分区存储与展示 |
| 少打扰 | 不默认读取剪贴板，不持续截图，不强制通知、语音、AI 或同步 |
| 数据可控 | 可查同步状态、修改记录、恢复误删、导出；隐私权限在服务端执行 |
| 能力诚实 | 截图保护、权限限制、离线缓存范围、提醒延迟与 AI 不确定性明确显示 |

### 1.3 本阶段明确不做

- iOS、macOS、Linux 原生采集端；不承诺 Android 的方法可以迁移为 iOS 任意 App 捕获。
- 绕过系统保护截图、后台连续观察屏幕、读取完整 UI 树或按键记录。
- 在任意第三方 App 原页面永久高亮；现有能力是截图批注，网页定位是另一个能力。
- 团队协作、公开分享社区、插件市场、复杂知识图谱、完整富文本排版系统。
- AI 自主修改／删除知识库，自动给用户下人格或心理诊断结论。
- 为达成统一知识库立即重写 Windows 为完整原生笔记客户端。
- 在未落实密钥、备份和恢复设计前宣称端到端加密或零知识存储。

## 4. 平台分工与页面结构

### 4.1 M1 各端职责

| 端 | 采集 | 查看与编辑统一库 | 离线范围 | 提醒 |
| --- | --- | --- | --- | --- |
| Android | 保留所有现有入口 | 原生列表、搜索、详情编辑、任务、回收站 | 本机记录、已同步元数据、已下载图片可用；未下载图片明确占位 | M1 指定的提醒设备 |

| Chrome／Edge 扩展 | 保留选文、截图、即时想法 | Outbox 与统一 Web 知识库分开，不各造一套完整编辑器 | 采集 Outbox 离线保留；浏览器重启后正式记录不丢 | M1 不承担后台提醒 |
| Web | 快速记一条 | 电脑主要知识库入口，同时适配手机浏览 | M1 不承诺关闭页面后的离线库；编辑中断网必须保住未提交草稿 | 展示到期／逾期；不承诺浏览器关闭仍提醒 |

### 4.2 信息架构

- 主导航：记录、待办、设置；M3 完成后才增加“回顾”。
- “记录”默认进入全部非回收站记录，可切换未整理、星标、归档；列表顶部为搜索和轻量筛选。
- 快速记录始终容易到达；Android 主入口不被权限说明大卡片长期挤到下方。
- 详情：我的想法 → 批注图片／原文证据 → 来源与时间 → 关联任务；技术 JSON 与诊断放入“更多”。
- 设置：采集权限、设备与同步、AI 与隐私、数据与备份、外观／快捷键、关于与诊断。
- Outbox 是传输队列；Inbox／未整理是内容整理状态。两者不能用同一个“收件箱”文案混淆。

## 5. 现有功能优化要求（M0）

### OPT-01 首次使用、首页与权限引导／P0

需求：

- 首次提供“先记一条”“启用跨 App 截图”“连接我的知识库”三个独立步骤；后两步可跳过。
- 按用户使用入口解释并请求权限；拒绝截图授权不影响文字记录／系统分享。
- 已完成的引导不反复出现；权限失效时展示紧凑提示与修复入口。
- 首页设置大卡片收敛为状态提示；常用操作为记录、搜索、最近内容。
- 不支持的系统版本、截图受保护、浏览器限制页分别解释；不能笼统要求“开全部权限”。

验收：全新安装、拒绝权限、返回设置授权、再次撤销、应用重启五种流程可重复执行；任何一步不配置服务器也能保存并回看文字。受保护内容不绕过，允许改为只记想法。Android 的安全窗口限制参考 [官方 FLAG_SECURE 说明](https://developer.android.com/privacy-and-security/risks/secure-flag)。

### OPT-02 截图触发、来源一致性与取消／P0

需求：

- 磁贴／快捷键触发后优先取得目标内容，不把触发页、菜单或自身工具栏误记成来源画面；以实机证据确认。
- 连续触发时只允许一个活跃采集会话，给出“正在编辑，可返回继续”的反馈，不覆盖原草稿。
- 浏览器选择文字的来源与截图必须属于同一标签页／采集会话；切页或导航导致不一致时提示重新采集或仅保存原文。
- 普通应用无法取得 URL／应用名称时保存截图与评论，来源显示未知，不编造链接。
- 无修改直接退出；有未保存修改则提供继续编辑、保留草稿、放弃三个动作。放弃清除该会话临时数据，不产生正式记录。

验收：连续触发三次、切换 App／标签页、打开菜单后触发、返回／Esc／窗口关闭均不覆盖先前草稿。以至少五类来源应用完成正常采集与限制负例。

### OPT-03 裁剪、查看缩放与坐标稳定／P0

需求：

- Android 裁剪框的边／角必须真实可拖动；框内可移动选区；最小范围、越界和反向拖动有确定行为。
- 编辑画布支持明确的查看／移动模式；手机双指缩放平移，桌面提供缩放与适应画面。查看操作不能生成笔迹。
- 修改裁剪范围不能静默清空笔迹。当前会话内缩小／再扩展应保留原笔迹，支持撤销裁剪。
- 浏览器补充真正的“裁剪保留区域”，与现有椭圆／方框标记工具分开；仅画一个方框不代表已排除框外像素。
- 正式保存只保留确认裁剪范围的像素。保存后重新裁剪只能缩小已有原图，不能恢复当时未保存的全屏区域；确需更多上下文应重新截图。
- “确认裁剪”指用户点击明确的“使用此区域／使用全图”动作，不以第一次触碰画布视为同意。确认后草稿只持久化该区域的图片与可见批注；范围外像素、越界笔迹、可还原它们的撤销栈和旧预览只在当前会话内存中保留。
- 再次确认更小范围时替换恢复草稿，清理旧范围缓存；正式保存时还要裁切／归一化矢量坐标、删除越界段和会话历史。会话结束后不能靠 JSON／撤销历史重建未保留区域；这属于应用数据清理，不宣称存储介质取证级擦除。
- 跨缩放、旋转、多屏 DPI 的坐标以同一明确坐标系持久化；矢量与预览保持一致。
- 编辑预览分辨率与保存源分辨率分开；优先从捕获源生成最终裁剪图，不因适应小屏就静默降低最终清晰度。内存／体积限制确需降采样时，展示最终尺寸与原因，用户可确认或取消；“100%”指一图像像素对应一显示像素的查看模式。

验收：先框选再缩放标注、移动选区、撤销裁剪、反向拖动、贴边框选与旋转后保存，原图／预览／矢量复渲染对齐。检查正式文件、恢复草稿、缩略图与矢量／撤销数据均无确认范围外可重建内容。测试固定图上的坐标变换往返误差不超过 1 个原图像素；人工实机核对混合 DPI 与触控命中。

### OPT-04 批注工具与输入焦点／P0；扩展工具／P1

M0 需求：

- 保留自由笔、荧光笔与浏览器已有圈／框；工具选中态、颜色和线宽可辨识，切换不丢内容。
- 各端补齐撤销／重做，包含画笔与裁剪的明确顺序；新操作之后重做栈清空。
- Windows 的 `Ctrl+Z`／`Ctrl+Y` 在评论输入框生效于文字，在画布生效于批注；不得全局吞掉输入框的撤销。
- `Ctrl+Enter` 保存、Esc 退出遵守草稿保护；输入法候选阶段和多行文字 Enter 不意外提交。
- M0 的详情图片可放大看清、切换原图与批注图；只存在压平图片的旧记录标为“不可拆分编辑”。已有记录追加／修改图层由 M1 的 LIB-03 提供，不伪造可编辑历史。

M2 扩展：统一补齐椭圆、矩形、箭头、对象删除、颜色／线宽选择。隐私遮挡必须是单独安全能力：真正外发的所有图片、OCR 与缩略图都已脱敏；画一个可移除色块不算脱敏，也不得默认同时外发未遮挡原图。

验收：画两笔、撤销、重做、切换工具、评论区编辑／撤销、保存再打开，结果一致。分别测键盘、鼠标、触控及中文输入法。

### OPT-05 草稿、退出与中断恢复／P0

需求：

- 草稿与正式记录分开；草稿不进入搜索、同步和 AI，不自动成为正式笔记。
- 文字和已确认裁剪区域内的批注，在修改停止后 1 秒内写入本机草稿；切后台／关闭前尽可能立即持久化，并显示草稿状态。
- 未确认范围的全屏原始帧不自动长期落盘；默认仅供当前会话。确认裁剪后可保留该区域作为本机恢复草稿，并提示用户。
- 修改选区前未提交的全屏内容若中断不可恢复，恢复评论／已确认区域并提示重新截图，不声称恢复了不存在的像素。
- 浏览器刷新编辑页恢复已持久化的评论、类型和标注；仅保存首次采集输入不算编辑草稿恢复。
- Windows 显示器拔插／DPI 变化或 Android 页面重建不是用户主动放弃；保存已确认区域与编辑草稿，再提供适配新画面的恢复入口，不静默清空。
- 默认草稿保留 7 天；设置可查看、立即删除或延长单条。明确放弃立即删除，保存成功后清理对应草稿；临时帧启动时清扫。
- Web 知识库编辑草稿默认仅保留当前标签页会话；刷新恢复，断网显示未提交。跨浏览器重启持久化须用户主动开启私人设备模式，退出时可清除。
- Web 草稿按服务器规范地址、知识库身份、记录／会话 ID 隔离。主动退出／切换库前提示处理未提交内容；默认会话草稿在确认退出后清除。私人设备保留的草稿在退出后锁定，重新认证同一库后才可恢复，不能展示或提交到另一个库。
- 凭证被撤销／失效时停止提交并锁定远程资料视图；当前编辑草稿可在本机保留等待重新认证，不因认证故障直接丢弃，且不得自动跨身份恢复。

验收：输入／批注后看到草稿已保存再强杀或刷新，恢复内容一致；在 1 秒落盘窗口内中断只允许丢失该窗口未确认持久化的操作，不能丢正式记录。检查草稿不上传、取消清理及 7 天过期逻辑；同一浏览器退出、切库、凭证失效后重登，不展示／提交其他身份草稿。Web 远程记录编辑与身份隔离的验收归 M1，M0 只验采集草稿。

### OPT-06 保存、重复点击与保存后去向／P0

需求：

- 点击保存先完成本地原子写入；只在记录和必需附件可重新读取后显示“已保存到本机”。
- 上传移到独立队列，不占用编辑 UI；本地失败不能显示成功，也不自动删除草稿。
- 连点／重复快捷键只产生一个正式记录 ID；丢失网络响应后的重试沿用同一 ID 与操作标识。
- ID 在草稿首次创建时分配并持久化；保存后的草稿清理失败单独标记并稍后重试，不能把已经成功的保存改报为失败，更不能重新分配 ID。
- 保存后提供“查看记录／继续记录”；浏览器不能出现“输入还能改，但保存按钮永久失效”的状态。
- 默认保存后结束当前编辑会话并返回来源／关闭扩展编辑页（平台允许时）；若停留则展示只读回执。M0 仅提供查看／新建下一条；M1 才提供“继续编辑当前记录”，进入 LIB-03 产生新修订，不再创建副本。
- 空白纯文字笔记不保存，提示写点内容；已有截图／来源原文时评论可空。超过限制说明具体字段与允许长度，不静默截断用户评论。

验收：快速点击保存 10 次只产生一条记录；看到本地成功后立即重启仍可读。模拟磁盘满、损坏图片、上传超时、保存成功后草稿清理失败及响应丢失，分别验证成功提示、草稿保留和同 ID 重试。保存后所有可编辑区域与提交动作保持一致。

### OPT-07 同步状态、失败解释与重试／P0

需求：

- 本地成功与网络状态分开；队列至少区分未连接服务、等待上传、上传中、已同步、失败待重试、冲突待处理。
- 显示当前条目状态、未完成数量、最近成功同步时间；只有上传能力时使用“上传”，不能误称完整同步。
- 网络断开／超时／429／5xx 使用带退避的可恢复重试；401／403、数据不兼容、文件过大等需要用户处理，不能无限高频重试。
- 错误提示包含下一步，例如“凭证失效，重新连接；你的记录已保存在本机”。技术错误码收进详情。
- 手动重试与后台队列共用幂等操作，不能重复入队；换服务器前说明原库与新库关系，不悄悄上传全部历史。
- 扩展 Outbox／最近记录的所有读改写需事务或统一串行协调，包括多个编辑页入队、批量 flush 与清理交错；只给 flush 上锁不算解决并发丢记录。
- popup、右键菜单、快捷键、磁贴和应用内入口的错误都必须用户可见，不能只输出控制台日志；不同入口共用原因与修复动作。

验收：断网创建 100 条，期间重启后再联网，记录与附件完整且不重复；20 个扩展编辑页并发保存，以及 flush 最后读取与提交之间插入新记录，全部唯一记录保留；依次模拟 401／403／409／413／429／503。失败原因和可操作按钮对应正确，日志不输出正文或令牌。

### OPT-08 列表、视觉、可访问性与快捷操作／P0

需求：

- 不在 UI 主线程扫描和解析整个本地库；列表分批加载、缩略图按需加载，详情返回保留滚动位置与筛选条件。
- 图文卡片突出自己的想法与图片，来源、时间、类型为辅助信息；`L2`、原始包名、JSON 等移入详情说明。
- 空库提供示例引导但不插入伪用户记录；无搜索结果、图片缺失、无网络、权限失效分别显示对应状态。
- 支持系统字体放大、浅／深色、触控大目标、键盘 Tab 焦点和按钮无障碍名称；状态不能只靠颜色区分。
- Web 在手机窄屏进入独立详情并可返回原列表，不以长页面滚动代替所有导航。
- Windows 提供快捷键修改、冲突检测和恢复默认；快捷键注册失败要提示，托盘仍可操作。

验收：360 CSS px Web 窄屏、Android 字体 200%、桌面键盘操作不遮挡保存／返回等关键动作；万条测试库中可找到最早记录，不卡死或整库加载原图。

## 6. 日常知识库功能（M1）

### LIB-01 统一资料库与清晰入口／P0

- Android 展示本机未上传记录与服务器记录的统一列表，以稳定记录 ID 合并，标记来源设备与同步状态。
- 首次连接分批获取元数据；图片按需下载，可为选定记录“离线保留”。未缓存图显示未下载，不显示图片损坏。
- Windows 托盘、扩展与 Android 设置提供相同的“打开知识库”入口；Web 作为电脑的主查看界面。
- M1 Android 离线搜索覆盖本机及已拉取元数据；首次拉取未完成时显示进度与范围，不能误报“全库无结果”。
- Android 内置详情支持稳定记录链接；Web 刷新或从引用链接打开能直达对应记录，先经过身份校验。链接不得携带访问令牌。

验收：浏览器创建 A、Windows 创建 B、手机创建 C；三条在 Web 与 Android 只出现一次，并能打开评论与图片。新手机分批同步期间继续创建 D，不丢失、不重复；离线打开缓存与未缓存附件时提示准确。

### LIB-02 搜索、筛选与完整历史／P0

- Android 增加全文搜索；Web 补齐列表与搜索分页。不要仅将 50／100／200 改成更大的固定数字。
- 搜索字段为评论、直接来源文字、已有 OCR、标题／来源 URL；显示命中字段和片段，不混成用户自己的话。
- M1 筛选：类型、日期范围、来源设备／应用、星标、归档；回收站单独搜索，默认不混入。
- 中文连续文本、英文词组、中英混排、emoji、标点都需测试；现有 FTS 与 LIKE 回退需核查召回，不能只覆盖英文。
- 时间列表使用包含时间与唯一 ID 的稳定游标；搜索按固定查询与确定排序分页。并发新增时不漏旧项，刷新后可看到新项。
- 显示“已加载 N 条／还有更多”；只有取得可靠总数才写“共 N 条”。快速输入时旧请求不得覆盖新结果。

验收：创建 10,000 条合成记录，其中 250 条时间相同、500 条命中同一关键词；全部翻页无重复遗漏，最早记录可找到。输入两个先后不同查询并反转响应顺序，只显示最后查询结果。删除、恢复、编辑后搜索索引一致。

### LIB-03 已保存记录继续编辑／P0

- Android 与 Web 可修改自己的评论、可选标题、类型、星标、归档和 AI 可见性；来源原文默认只读，用户纠错另存说明。
- 详情提供显式“编辑”，进入编辑后自动保存本地草稿；“完成”提交正式修订。不要每次按键生成一条服务端历史。
- 图片记录支持追加／修改可识别的矢量层，保留原始裁剪图；旧压平图只能追加新层。
- 同一条记录保留创建时间，更新修改时间与修订号；至少保留最近一次用户可恢复的编辑前版本。完整历史可后续扩展。
- 取消编辑只取消本次未提交变更；同步冲突时可查看服务器版本、本机版本并选择合并或保存独立副本。
- AI 权限变更和删除不能使用“最后写入覆盖”；冲突解决前采用更保守可见性，不能因旧离线编辑重新授权。

验收：在安卓修改评论，Web 可见且记录数不变；两端离线改同一记录，重连时双方内容可恢复，没有静默覆盖。把权限收紧后，旧端携带旧权限更新应冲突或保留收紧策略。

### LIB-04 整理、回收站与批量操作／P0

- 类型、星标、归档是独立维度；归档只是离开未整理视图，不等于删除，也不改变 AI 权限。
- 支持多选星标、归档、移入回收站；批量操作显示目标数量，失败逐项反馈，不显示虚假全成功。
- 移入回收站可短暂撤销；回收站可恢复。M1 默认不自动彻底清除，保留期限若以后改变需显式说明。
- 彻底删除需二次确认，并说明关联任务、AI 派生内容和离线设备的影响；不得默认为同步失败的解决方式。
- 旧记录升级后默认处于未归档、非星标状态；不自动判断“是否已处理”。

验收：跨两设备批量删除／恢复含图记录，状态最终一致；归档后仍可在全部记录搜到。部分失败时正确保留未成功条目并可重试。

### SYNC-01 配对、设备授权与退出／P0

- 保留自托管单用户模式，不强制注册商业账号。M1 在已认证的 Web 中生成短期配对码／二维码。
- 配对码单次使用、默认 5 分钟过期，限制尝试频率；二维码不包含可长期复用的全库主令牌。
- 新设备展示服务器域名、设备名、读取／写入范围，经用户确认后换取设备凭证；AI 凭证与第一方设备凭证始终分开。
- 服务端为设备分配身份并可单独撤销。现有 Write Token 仍不能读取全库，不能为了扫码方便直接扩权。
- 连接测试区分服务可达、认证成功、读取能力、写入能力；若测试需要写入数据应先说明，不能静默创建测试笔记。
- 旧服务器不支持配对时提示升级，保留现有手填上传配置但明确其能力；不展示不可用的“已连接全部设备”。
- 退出／撤销连接停止新同步，说明本机资料是否保留；默认不删除本机内容。撤销无法隔空保证已经离线的设备缓存立刻消失。

验收：过期码、重复扫码、错误域名、撤销设备、只写旧凭证、只读凭证、AI 凭证分别验证。撤销后的下一次服务请求必须拒绝；日志、URL、剪贴板历史与普通导出不出现主令牌。

### SYNC-02 增量读取、编辑合并与附件／P0

- 新客户端以规范适配层接纳各端记录，不把浏览器／Windows 的 ID 或字段硬塞入仅支持 Android 本地格式的解析器。
- 明确本机操作 ID、服务端修订、同步游标的职责；重试不得生成新操作／新记录。
- 首次分页读取与后续变更衔接要覆盖读取期间发生的新建、编辑、删除；不能只取前 200 条作为初始同步。
- 每页变更与游标在本机事务中共同提交，进程中断可重放；事件无序、重复、过期时不覆盖较新修订。
- 现有 change envelope 的历史 revision 与附带当前 record 可能不同：先修订／明确接口语义，不能假定它是完整逐版本快照。
- 元数据与附件状态分开。元数据已同步但图片未下载时，显示“已同步，图片未缓存”，不反复上传自己的附件。
- 本阶段优先复用完整附件上传，不要求分块续传；仍须设定大小限制、校验完整性并保留失败源文件。

验收：首轮读取期间另一设备修改／删除／新建，最终两端一致；在落库／提交游标之间模拟崩溃可恢复。同一页重复三次、旧事件晚到、附件下载中断不产生重复或降级覆盖。

### SYNC-03 删除传播、清除与缓存／P0

- 移入回收站与彻底删除均有持久事件；彻底删除后保留最小防复活标识，禁止旧端用同一记录 ID 再次创建。
- 删除与离线编辑冲突时保留待处理说明，不自动复活；用户确需保留可明确创建新 ID 的副本。
- 清除关联图片、全文索引、OCR、后续向量／摘要／记忆引用与已联网设备缓存；共享 Blob 仅在无授权引用时物理删除。
- 活动服务中完成清除后不得再检索／下载该内容。离线设备下次同步时清理；备份按已声明周期轮换，不承诺瞬间删除全部离线副本。
- 恢复服务器备份后必须重新应用备份之后的删除登记；不得让已要求彻底删除的内容重新对外可见。
- 删除登记不能只存在于将被旧快照覆盖的数据库；W0 必须设计独立于被恢复快照的持久登记与恢复副本，记录覆盖截止点。若要承诺数据盘故障恢复，也必须有不与该盘共故障的登记副本，不擅自创建第三方备份账号。
- 旧快照恢复先合并完整删除登记再开放 API／AI。登记缺失或覆盖不足时停止自动上线，报告风险并要求用户决策；不能声称此时仍能保证无复活。

验收：设备 A 离线持有记录，B 彻底删除，A 重传应被拒绝且不复活；修改同 ID／更旧 revision、重新配对、从旧备份恢复均测试。再演练“当前库丢失，仅剩旧备份＋独立删除登记”及“登记缺失”，前者可安全恢复、后者不能自动开放访问。删除含共享图片的一个记录，不损坏另一个仍有合法引用的记录。

### TASK-01 从想法到行动／P0

- 引入独立任务对象：标题、可选的用户行动说明、`open/done/canceled`、来源记录 ID（可空）、字段来源、截止时间、提醒时间、完成时间、修订与删除状态。
- 记录详情“转为待办”默认从评论生成可编辑标题，用户确认后创建任务；普通笔记内容与原始 `kind` 不被自动改写。
- 旧 `kind=todo` 记录首次迁移为一条对应任务；映射 ID 稳定、可重复执行、不自动设置截止／提醒、不重复生成。
- 新服务器继续接受旧客户端新增 `kind=todo`，通过同一映射幂等补建任务。旧端更新来源评论不覆盖用户已编辑的任务标题／状态；将类型改为普通笔记不自动删除或取消已有任务。
- 现有 MCP `list_todos` 保持只读和兼容的记录形态，对未完成任务的授权来源记录做服务端查询与去重，不再先取最近 200 条。M1 不新增独立任务 MCP 工具；无来源任务的 AI 读取归 M3，启用前必须具备独立且默认保守的 AI 权限与服务端过滤，不因任务已保存而默认开放。所有类型／返回形态变更在 W0 冻结并补兼容测试；未升级 MCP 前不能宣称 AI 已能读取完整任务系统。
- 待办页有全部未完成、今日、逾期、已完成；无日期任务可见。支持完成、撤销完成、取消、稍后提醒，暂不做子任务／重复任务。
- “今日”按用户当前时区显示，存储区分日期型截止与绝对提醒时间；只设置日期不自动在午夜发提醒。
- M1 默认只由用户选定的一台 Android 设备提醒；其他设备可管理任务但不重复弹窗。换设备／关闭权限后明确提示提醒不可用。
- 用户首次设置提醒时再申请通知权限；拒绝后任务仍保存，显示站内到期状态与修复入口。系统后台限制下不保证秒级到达。参见 [Android 通知权限说明](https://developer.android.com/develop/ui/views/notifications/notification-permission)。
- 完成／取消任务移除本机未来提醒；同一已知修订与提醒实例不重复发送。设备离线无法知道另一端已完成时可能出现旧提醒，重新联网校正并明确限制。
- 删除来源笔记不自动删除任务。手动新建任务的标题／用户行动说明可独立保留；从来源自动填入的标题和摘录标为派生字段，确认／编辑不自动抹掉来源依赖。来源移入回收站时暂停其派生 AI 使用，彻底删除后清除派生文字并显示“来源已删除的待办”，保留独立行动说明，用户可重新填写标题；UI 事先告知这一影响。

验收：离线创建任务、设置提醒、重启设备、拒绝通知、切换时区、在另一端完成、撤销完成逐一验证。旧 TODO 迁移执行两次数量不变；新服务上线后旧客户端继续创建／改类型、现有 MCP 查询均按兼容规则工作。先造 300 条非 TODO 再查更早任务，不能因近期记录截断漏任务；清除来源时独立行动说明保留、来源派生文字清除。

### DATA-01 可导出、可恢复与存储管理／P0

- 保留现有 ZIP 导出并扩展任务、新字段与格式说明；不把目标模型当成现有已导出的字段。
- Android 在未配置服务器时也可通过系统文件选择器导出本机正式记录与附件；Windows 保留本地文件读取／复制说明，扩展提供未上传 Outbox 导出。不能要求“先上传到云端”才能救回唯一的本地资料。
- M1 必须有可实际操作的本产品备份恢复路径：Android 通过系统文件选择器导入 Mnote 本机备份并预览数量／冲突，不能要求普通用户访问受保护私有目录；扩展可恢复自身 Outbox 包，Windows 提供验证过的本机恢复工具／流程。默认去重并保留冲突副本，不覆盖新内容。此最小恢复不等于 M2 通用跨来源图形导入器。
- 设置显示记录数、本机附件大小、缓存大小、同步异常数；“清理缓存”不得删除未上传原件、离线保留资料或草稿。
- 明确区分用户开放导出与服务器灾难恢复备份。M1 可沿用受控命令行恢复，不要求先开发完整图形导入器。
- 交付空库恢复和已有库恢复方案、预检报告、计数／哈希校验、失败回滚；禁止未经预览直接覆盖现有个人库。
- 查看备份功能未与实际部署连接时显示“未配置／未知”，不能根据存在脚本就显示备份成功。
- 备份的数据库快照与图片集合必须一致；并发写入／purge 时通过适当快照、GC 协调或短暂受控维护保证每个引用附件存在，并记录策略。不能仅验证压缩包自身哈希就判定可恢复。
- 大库导出不能将整包多次读入内存；采用有界内存的流式或后台任务，超限／取消可清理中间文件且不影响原库。
- 普通导出是敏感文件，默认不含令牌／私钥／凭据；除非确实提供加密包，否则提示“导出文件未加密”。

验收：用包含图文、任务、回收站、旧格式记录的合成库导出，在隔离目录恢复，核对 ID、时间、关系与附件哈希；未配对手机的本机记录也可完整导出并恢复。并发写入／purge 的备份演练不得缺失引用附件。损坏包／路径穿越／重复导入被安全处理；不读取目标目录外文件、不覆盖较新数据。

## 7. 内容理解与组织（M2）

### OCR-01 截图文字提取／P1

- 优先处理用户确认的裁剪图；整张图 OCR 与圈选区域优先级明确区分，不能读取未保存的全屏上下文。
- OCR 异步执行，不阻塞保存；状态为未请求、等待、处理中、完成、失败／不支持，失败不影响图片和评论。
- 优先评估设备本地／个人服务器方案；不擅自把图片传到第三方。远程 OCR 必须由用户选供应商与授权。
- M2 默认保存文本、语言、引擎版本及引擎实际可提供的区域坐标／置信度；拿不到置信度时为空，不伪造分数。
- OCR 与直接来源文字分别显示，允许用户纠错并保留原识别结果；重跑生成派生版本，不覆盖评论。
- OCR 完成后更新索引，并可复制识别文字、点击片段查看对应区域。识别失败支持手动重试。

验收：至少 30 张经授权合成／公开测试图覆盖清晰中文、英文、混排、深色背景、长图、旋转、低清与空白。报告字符错误率与失败数；首轮目标为清晰印刷体中文／英文子集字符错误率不高于 10%，不把手写或所有真实截图纳入相同承诺。重试、索引更新、权限拒绝与源图删除后清理均通过。

### ORG-01 轻量整理与关联／P1

- 提供用户可选的主题／标签，允许一条记录属于多个主题；不要求创建复杂目录后才能记录。
- 支持手动关联记录与“同一来源的其他记录”。用户可填写“为什么记下它”，不作为必填。
- 自动标签或相似记录推荐必须标成建议，由用户接受；模型未配置时手动功能仍可使用。
- 内容哈希可用于提示重复采集，但同一网页的不同时刻／不同评论保留为独立记录；不自动删除相似内容。
- 语义搜索作为后续单独能力，不能以有 OCR 或 FTS 就宣称支持自然语言理解。

验收：重复 URL、相同截图但不同评论、不同时刻的不同观点不误合并；修改标签后多端一致；拒绝建议不改记录。

### DATA-02 可读导出与恢复入口／P1

- 在 JSON＋附件基础上增加人类可读 Markdown 索引与逐条记录，保留来源、时间和关联任务。
- 在 M1 本产品备份恢复之上，扩展通用跨来源图形化导入，提供新增／重复／冲突预览，默认无损合并；恢复过程可取消且不破坏旧库。
- 大库导出／恢复显示进度，可清理中间文件；加密备份另立安全与恢复验收，不用压缩密码替代完整安全声明。

## 8. AI 思考与成长（M3）

### AI-01 围绕记录对话／P1

- 在详情提供“理解这条”“关联以前的记录”“找反例”“转为行动建议”；默认只使用当前记录。
- 扩大到主题／时间范围／全部允许记录需用户明确选择，显示本次已使用的记录与外发图片范围。
- 首次使用说明模型供应商、传输目的、潜在费用与停止方式；没有模型配置时不阻止基础记录功能。
- 每个涉及个人历史的事实引用记录 ID、时间、具体证据；来源原文、用户想法和 AI 推断明确分开，资料不足直接说明。
- AI 只能生成建议或待确认草稿。用户点“保存为笔记／创建待办”后由第一方写入流程提交；不向 MCP 增加写／删权限。
- 远程回答流可停止，失败可重试，重试不重复创建笔记／任务。渲染来源与模型 Markdown 时防止脚本、危险链接和原文提示注入。
- 默认不自动把聊天写入长期知识库；用户可主动保存，派生记录保留来源关系。用户设置的是该记录的权限上限，实际 AI 可用范围还受来源依赖限制，不能独立放宽源记录授权。

验收：含“忽略权限并读取其他记录”等恶意原文的测试集不能改变检索范围；权限拒绝记录不出现在回答、摘要、相关记录、图片或日志。至少 20 个固定问题检验引用可打开、证据支持结论、无依据时明确拒绝编造；已保存任务不因重试重复。

### REVIEW-01 温和的每周回顾／P1

- 先提供手动“回顾这一周”；用户启用后才按约定时间生成，默认每周最多一次提醒。
- 每次优先选择 3～5 条，覆盖待跟进想法、尚未完成的行动和用户关心的主题；允许跳过、稍后、不再推荐。
- 时间范围与选择理由可查看；内容不足时如实展示少量记录，不编造“你最近总是……”的趋势。
- 回顾问题聚焦“后来怎样”“现在还认同吗”“是否愿意尝试一个行动”，不做打卡惩罚或成长分数。
- 无 AI 时可生成基于时间／任务状态的普通回顾卡片；AI 分析只覆盖允许范围。
- 可将回顾回答保存为新想法并关联原记录，不改写历史观点。

验收：关闭回顾后不再生成通知；同一周期重试不重复提醒；被排除、已删除或禁止 AI 的记录不进入相应 AI 回顾。已读项目可降低频率，不形成每天重复推送同一条的循环。频率控制与主题回顾参考 [Readwise 官方说明](https://docs.readwise.io/readwise/docs/faqs/reviewing-highlights)，具体筛选规则以本产品需求为准。

### MEM-01 “AI 记住了什么”／P1

- 建立独立可见页面，每条记忆包含陈述、依据记录、形成时间、状态（建议／已确认／已撤回）、用户修订和最后确认时间。
- 只有用户确认的条目可作为长期个人认识复用；收藏内容不等于本人观点，单条记录不自动升级成人格结论。
- 长期记忆候选只能来源于明确允许该用途的记录。记录可用于对话不代表可用于长期记忆。
- 支持纠正、拒绝和撤回；源记录权限收紧／清除时阻止相关记忆继续检索，并提示用户检查独立保存的结论。
- 明确“在 Mnote 中停止使用／删除派生记忆”的范围；对已经外发给第三方的内容不能宣称可撤回所有副本。

验收：未确认建议不参与新会话长期上下文；同一主题的观点变化保留时间线而非覆盖成单一标签；撤回记忆、删除来源、降低权限后，重新检索和新会话不得继续使用已失效信息。

## 9. 数据语义与兼容约束

以下是必须表达的产品字段，不是要求立刻切换为某份尚未实现的线协议。新增字段／表名在技术设计中确定，并同步更新测试和协议文档。

| 对象 | 最少语义 | 关键约束 |
| --- | --- | --- |
| 记录 | 稳定 ID、创建／修改时间、设备来源、评论、原文、图片、矢量、类型、星标／归档、AI 策略、服务端 revision | 原始时间与证据不因同步改变；保留未知字段 |
| 本机草稿 | 会话 ID、已确认裁剪、评论／类型／批注、保存时间、到期时间 | 不同步、不进入 AI；与正式记录分开 |
| 待同步操作 | 操作 ID、目标 ID、基线 revision、修改内容、重试状态 | 与本机正式变更一同持久化；重试复用 ID |
| 任务 | 稳定 ID、标题、状态、时间、来源 ID、完成时间、revision | 从旧 TODO 幂等迁移，提醒不是任务本身 |
| 图片与派生结果 | 角色、哈希、尺寸、来源 revision、缓存状态、隐私版本 | 不把缩略图或 OCR 冒充原始证据 |
| 删除登记 | 记录 ID、清除版本／时间、最小防复活信息 | 不保留被删除正文；独立于可被 purge 删除的记录行 |
| 设备 | 服务端身份、显示名、授权范围、撤销状态、同步进度 | 不把可伪造客户端 device ID 当成鉴权依据 |
| AI 派生内容 | 来源 ID／revision、生成时间、用途、可见策略、用户确认状态 | 派生内容不能绕过来源的授权和删除 |

### 9.1 来源依赖、派生内容与用户独立表达

- 从来源复制的摘录、自动填入的任务标题、AI 摘要／记忆、OCR、向量等均为派生内容；主动点保存或改几字不自动移除来源依赖。
- 用户从空白手动撰写的记录／任务、在独立字段输入的行动说明／补充思考属于独立表达；不因为有关联链接就随来源清除而删除。
- 多来源派生内容的有效 AI 权限为自身设置与所有依赖来源的最保守交集；允许远程对话但禁止记忆的任一来源会阻止整段进入长期记忆。
- 来源权限收紧／移入回收站后，相关派生内容先停止不再被允许的 AI 读取／检索；不静默删掉用户独立表达。重新生成只依赖允许来源的摘要需明确操作并产生新派生版本。
- 来源彻底删除后，清除直接复制和自动生成的依赖字段、索引与缓存；多来源生成字段无法证明已剔除被删来源时整体清除。保留独立表达与“部分来源已删除”占位，并默认停止该混合记录的 AI 使用，待用户检查后重新设定合适权限。
- 这套规则贯穿任务、保存后的 AI 笔记和记忆；M1 先实现任务字段来源，M3 扩展到 AI 对象。必须验收“多来源摘要 → 保存笔记／任务 → 收紧或删除一条来源”的完整链路。

迁移要求：

1. 核对真实 Android camelCase 本地格式、Windows／扩展格式及服务器 `schema_version:1`，建立脱敏 fixtures 和无损适配测试。
2. 升级前备份；新增迁移可重复执行并验证中断恢复。不要为了新字段清空本地目录或服务器库。
3. 旧客户端读不懂新字段时不应在整条 PUT 中抹掉它们。优先增量更新或服务端保留未修改字段，禁止把返回对象无差别写回。
4. 当前 `base_revision`、资产上传形态与返回引用不同，编辑请求必须有明确适配；不能假设 GET 返回值原样 PUT 可无损更新。
5. 新功能服务端先部署兼容层，再允许客户端启用；能力不支持时返回可理解错误，不静默降级成数据丢失。
6. 回滚不是运行旧二进制并期望它懂新库。迁移设计必须说明可回滚代码范围、不可逆步骤和恢复路径，先在副本演练。

### 9.2 隐私开关必须分清

| 控制 | 含义 | 默认与限制 |
| --- | --- | --- |
| 服务器同步 | 是否将本机记录复制到用户连接的服务器 | 保留现有显式连接行为；若新增逐条“仅本机”需独立字段，不能复用 `local_only` |
| `deny` | 不允许 AI 使用 | 第一方用户查看不受影响 |
| `local_only` | 不允许远程 AI 读取 | 保留旧默认；没有本地模型时不自动执行 AI，不代表禁止个人服务器存储 |
| `remote_no_memory` | 允许远程读取／当前对话，不用于本应用个人长期记忆 | 不等于第三方零保留；会话保存需独立明确操作 |
| `remote_memory` | 允许提出长期记忆候选 | 仍需用户确认，不能自动写入已确认记忆 |

“仅本机”若用于一条已上传记录，必须说明需要撤回服务器副本并等待联网确认；在撤回完成前不能显示“服务器已无此记录”。所有新控件都必须配套执行逻辑，不能只改文案。

## 10. 非功能要求与可衡量目标

以下为拟定验收目标，不是当前性能成绩。开发开始时记录基准设备和测试环境；不达标须定位、优化或让用户接受明确的范围调整，不能事后缩小测试集冒充通过。

阶段适用：M0 验收采集保存、草稿、现有上传、列表渲染、权限与现有格式升级；M1 追加全库搜索、跨端时延、任务、设备授权与恢复；M2／M3 追加各自 OCR／AI 派生规则。不以尚未进入该里程碑的指标阻止标明范围的 M0 修复版。

### 10.1 性能和可靠性

- 基准数据：10,000 条元数据，其中 1,000 条带 1080p 截图；另测 8 MP 单图。记录实际字节大小、设备内存、系统版本。
- Android／Windows 点击保存至本地持久化成功：基准截图 P95 ≤ 2 秒；不计用户输入时间与网络上传，后台操作不冻结交互。
- 本机已索引列表首屏 P95 ≤ 1 秒、搜索 P95 ≤ 500 毫秒；网络检索单独测量，不混入本地指标。
- 两端前台且在线、服务健康的场景，从一端提交成功到另一端主动刷新可见 ≤ 5 秒；不承诺系统杀后台后的实时推送。
- 每个性能指标预热后至少执行 30 次并记录 P50／P95、最大值；不得只报告一次最好成绩。
- 无已确认保存的数据丢失、静默覆盖、未授权泄漏或清除后复活。这些是发布阻断问题，不能以平均成功率抵消。

### 10.2 隐私与安全

- 默认不上传使用分析；需要时用户主动启用。验收指标先通过本地测试统计，不额外建立行为跟踪系统。
- 服务端执行记录／图片／搜索／OCR／摘要的权限过滤；不能只在前端隐藏。
- 日志和诊断导出默认排除截图、正文、完整查询、敏感 URL 参数和凭据；审计只保存必要的时间、操作、调用方与受控引用。
- 浏览器令牌不放 URL、公共页面存储或网页内容；配对与会话遵守同源、最小授权、撤销与有效期约束。
- 不为“更方便”增加后台剪贴板监控、全站永久读取、持续录屏或默认悬浮窗权限。
- 彻底删除的备份残留窗口、设备离线清理限制、未加密导出都要如实告知。

### 10.3 发布与升级

- Android 包名保留 `com.codex.mnote`，升级 versionCode；验证覆盖安装保留本机记录、草稿、队列与凭据。
- 核对上一安装包签名；若无法使用兼容签名，不要求用户直接卸载丢库，先交付导出／迁移与用户选择。
- Windows 不擅自迁移／清空既有 Inbox 路径；浏览器更新保留 Outbox；服务反向代理子路径保持兼容。
- 安装包、EXE、扩展 ZIP、服务端版本给出对应提交、SHA-256、签名状态、已知限制与安装方式。

## 11. 验收矩阵与发布门槛

需求章节的验收均为必测。下面列出跨模块发布阻断场景，供接手 Agent 建立集成测试与证据清单。

| 用例 ID | 场景 | 必须观察到的结果 | 阶段 |
| --- | --- | --- | --- |
| ACC-01 | 普通 App 截图、裁剪、标注、评论、保存、立刻重启 | 图片／评论／矢量一致，本地成功真实可回读 | M0 |
| ACC-02 | 权限拒绝、保护窗口、版本不支持 | 不绕过，不假成功，文字记录仍可用 | M0 |
| ACC-03 | 调裁剪、缩放、旋转、撤销重做、中文输入法 | 无笔迹误清空、坐标漂移或焦点快捷键误操作 | M0 |
| ACC-04 | 编辑强杀／刷新、取消、草稿过期 | 按明确草稿范围恢复；放弃不产正式记录、不上传临时帧 | M0 |
| ACC-05 | 连点保存、响应丢失、上传超时、断网 100 条 | 本地安全，同 ID 重试不重复；错误可处理 | M0 |
| ACC-06 | 旧版本覆盖安装／旧格式迁移中断再执行 | 原始记录、队列、权限不丢；新字段不被旧客户端抹除 | M1 |
| ACC-07 | 过期配对码、重复使用、设备撤销、错 scope | 凭证边界有效，旧写令牌没有读取权限 | M1 |
| ACC-08 | 三端新建、首次拉取时并发修改、游标中断 | 记录最终一致，无漏项、重复、游标跳过 | M1 |
| ACC-09 | 同时间大量记录、深度分页、中英文查询、响应乱序 | 全部历史可找到，最新查询正确展示 | M1 |
| ACC-10 | 两端离线改同一条、其中一端收紧 AI 权限 | 双方变更可恢复，更保守权限不被旧版覆盖 | M1 |
| ACC-11 | 软删／恢复／彻底删除后旧端重传、旧备份恢复 | 不复活，不泄露；合法共享附件不误删 | M1 |
| ACC-12 | 旧 TODO 迁移、跨端完成、拒绝通知、时区变化 | 任务不重复，状态同步，提醒边界准确 | M1 |
| ACC-13 | 导出、隔离恢复、坏包、清理缓存 | 原件可恢复，路径安全，不删唯一未上传副本 | M1 |
| ACC-14 | OCR 成功／失败／重试／删除／纠错 | 保存不阻塞，来源分离，索引更新且授权有效 | M2 |
| ACC-15 | 恶意来源、禁止 AI 记录、模型失败／停止 | 范围不扩大，无越权引用或重复任务 | M3 |
| ACC-16 | 周回顾关闭／跳过，记忆未确认／撤回 | 无继续打扰，失效记忆不进入新会话 | M3 |

验收环境：

- Android 至少一台 Android 11 和一台较新受支持系统实机，补充目标用户实际机型；权限、旋转、后台限制与通知必须实测。
- Windows 11 真实机器，单屏＋双屏负坐标＋125%／150% 混合 DPI；Wine 烟测不替代实机结论。
- Chrome 与 Edge 实际加载扩展，测试普通网页、动态导航与浏览器禁止页面；记录浏览器版本。
- 独立测试服务器与合成数据，模拟断网、高延迟、认证失效、429／503、进程中断和磁盘不足；不得拿个人真实库做破坏性测试。

交付证据至少包含：需求 ID → 实现提交 → 测试名称／操作步骤 → 结果 → 日志／录屏／数据校验路径。结果使用未执行、通过、失败、阻塞、不适用；缺设备只能标待实机验收，不得以构建成功替代。

发布门槛：所交付里程碑全部 P0 用例通过，无未解决的数据丢失、越权读取或清除复活；明确兼容矩阵、回滚方法与剩余限制。未满足时可交付标明缺口的测试候选，不可称该里程碑完成。

## 12. 开发拆分、依赖与交付要求

### 12.1 建议工作包

| 包 | 负责内容 | 前置依赖 | 主要交付 |
| --- | --- | --- | --- |
| W0 基线与契约 | 核查现状、合成 fixtures、记录／任务／隐私／迁移与同步契约 | 无 | 差异清单、技术决策、契约测试、分支计划 |

| W2 数据与同步服务 | SYNC-01～03、迁移、设备授权、稳定分页、字段保留 | W0 | 向后兼容接口、权限／冲突／墓碑测试 |
| W3 Android 知识库 | LIB、M1 同步状态／统一列表、下行缓存／编辑、任务 UI | W0；接入依赖 W2 | 新首页、资料库、编辑、搜索与离线状态 |

| W5 任务与提醒 | TASK-01 模型、迁移、指定 Android 提醒端 | W0、W2；与 W3／W4 共用任务契约 | 任务闭环、去重与时区测试 |
| W6 数据交付与总验收 | DATA-01、升级／恢复、集成验收与制品 | W1～W5 集成 | 安装包、版本清单、恢复演练、验收矩阵 |
| W7 内容理解 | OCR-01、ORG-01、DATA-02 | M1 完成 | M2 独立版本与测试集 |
| W8 AI 与回顾 | AI-01、REVIEW-01、MEM-01 | M1；模型与隐私选择已确认 | M3 独立版本、证据引用与权限回归 |

并行规则：

- W0 先统一 ID、时间、revision、授权、任务和删除语义；不得让多个 agent 各写一套数据模型。
- W1 可与 W2 并行；W3／W4 可使用 W0 确认的 mock 契约并行，但最终必须接真实服务验收。
- W1 再按平台分 owner：Android 负责磁贴／编辑器／本机列表，Windows 负责覆盖层／网络异步／快捷键，扩展负责队列／编辑状态／来源一致性，Web 负责现有列表／错误／窄屏查看优化；共享保存和隐私语义不各自定义。
- 每个共享文件／迁移／API 有明确 owner；其他 agent 通过契约协作，避免同时改写 `store.py` 或同一迁移。
- 不在 M0 为等待 OCR／AI 接入阻塞保存可靠性修复；不在基础授权未完成时上线 AI。

### 12.2 每个工作包的完成定义

1. 完成范围内全部需求与错误／空／加载／离线状态，不只交付正常路径 UI。
2. 增加或更新对应测试；复用现有 `scripts/verify-mnote-v1.sh`，适当扩展，不删除旧门禁掩盖回归。
3. 提供数据兼容、升级与回滚说明；凭据、用户数据和真实截图不进入仓库。
4. 发布代码到独立分支并给出可复核提交；无授权不强推、重写历史或直接升级用户的生产服务。
5. 标明自动化通过、人工通过、待实机验收分别是什么，不将历史版本证据当成本版证据。
6. 修改协议或产品范围时同步更新本文相应条目及当前契约文档，说明原因与取舍。

### 12.3 可直接复制给开发 Agent 的任务说明

> 请基于 `docs/mnote-vnext-product-requirements.md` 开发 Mnote。先核对当前仓库、分支、用户已有改动和文档现状差异，复用现有 Android／Windows／浏览器／服务器能力。默认先实施 W0，给出 M0＋M1 的任务拆分、数据兼容策略与验收计划，再按用户分配的工作包开发；不要一次展开 M2／M3。为范围内每个需求 ID 提供实现和测试证据。保持本地保存可靠、原文与用户观点分离、读写／AI 权限隔离、同步冲突不覆盖、删除不复活。使用独立分支并保留可回滚提交，完成代码推送到核实过的 Mnote 远端。不要清空个人库、绕过截图保护、擅自接入付费服务或公开部署。缺少实机条件就标明待验收，不宣称通过。

## 13. 默认选择与需要用户确认的事项

为避免开发 agent 因一般偏好反复停下来，以下默认可以用于技术方案；它们是建议，不是已上线能力。

| 问题 | 本文默认 | 何时必须确认 |
| --- | --- | --- |
| 电脑在哪里看记录 | Windows 托盘／扩展打开响应式 Web | 若要增加完整原生桌面知识库或桌面全库离线编辑 |
| 服务模式 | 保留个人自托管、单用户模式 | 改为商业云账号／多租户、修改生产域名／部署 |
| 提醒 | 一台指定 Android 设备，用户主动设定 | 要求跨端抢占去重、准点强保证、邮件／短信／外部日历 |

| OCR | 先评估本机／个人服务器，不自动外发 | 模型下载明显增加安装体积／成本、第三方云 OCR |
