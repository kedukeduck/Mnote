# Mnote V1 Core 交付契约

- 状态：本次可执行交付的范围基线
- 日期：2026-08-31
- 平台：Windows 11 x64、Android 11+、Chrome/Edge 桌面版
- 目标：先把“任何普通应用都能留下可回看的像素证据和我的想法”做成可用闭环

## 1. 这一版到底承诺什么

当内容出现在 Windows 或 Android 的任意普通应用中，只要操作系统允许截图，用户可以主动触发一次截图、选择需要的区域、划线或用荧光笔标记、写评论并保存。网页额外支持保存浏览器直接交付的选中文字、网址和定位锚点。没有网络时先保存在本机；配置个人 Capture Server 后再同步到统一 Inbox，并通过只读 MCP 供 AI 检索。

这里的“任意应用”是**像素级捕获覆盖面**，不是向第三方应用注入代码，也不保证每个应用都能交付精确文字。

本次发布是否成功，以本文件的 Core 闭环为准；[完整产品规格](universal-capture-v1-product-spec.md)中超出本文的 OCR 坐标、UI Automation、任务对象、端到端加密、断点续传等条目是后续增强目标，不能在本次发布说明中冒充已经实现。

## 2. Core 闭环

```text
任意普通应用中的内容
  -> 用户主动按快捷键、磁贴或应用内按钮
  -> 操作系统允许的一次截图
  -> 选择区域并用自由笔/荧光笔标记
  -> 写评论，标为想法、评论、稍后处理或 TODO
  -> 原图、批注图、结构化 JSON 本地成功落盘
  -> 可选同步到个人服务
  -> Inbox 搜索和只读 AI 工具按记录 ID 返回证据
```

“本地成功”与“已同步”是两个状态。网络失败不能撤销已经完成的本地保存，也不能显示成数据丢失。

## 3. 平台能力

### 3.1 Android 11+

必须具备：

- 应用内“全局摘录”入口；
- 快捷设置磁贴；
- 用户看过独立披露并主动启用的辅助功能截图服务；
- 单次截图，不持续录屏，不读取 UI 树，不监听输入；
- 矩形裁剪、自由笔、荧光笔、撤销、评论和类型；
- 同时保存未批注原图、压平批注图和矢量批注 JSON；
- `ACTION_PROCESS_TEXT` 精确文字入口；
- Android 分享文字/图片入口；
- 快速想法/TODO；
- 应用私有本地 Inbox；
- 可选 Capture Server 设置、自动重试和手动同步。

Android 11 以下可以安装现有 Mnote 功能，但全局单次截图入口不可用，界面必须明确说明系统版本限制。

### 3.2 Windows 11 x64

必须具备：

- 便携单文件 EXE；
- 系统托盘入口和 `Ctrl+Shift+F9` 全局快捷键；
- 捕获完整虚拟桌面，支持多显示器与负坐标；
- 冻结画面后矩形选择；
- 自由笔、荧光笔、撤销、评论和类型；
- 同时保存未批注原图、压平批注图和矢量批注 JSON；
- 记录可取得的前台窗口标题、进程路径和屏幕坐标；
- 取消时不产生正式记录；
- `%LOCALAPPDATA%\PersonalCapture\Inbox`（为兼容既有测试数据保留的实际目录名）；
- 可选同步到 Capture Server；上传失败时本地记录仍然成功，并可从托盘按同一记录 ID 手动重试。

V1 Core 不承诺 Windows UI Automation 精确选区，也不承诺窗口/自由形选择。所有普通应用以截图 L2 为保底。

### 3.3 Chrome / Edge

必须具备：

- Manifest V3；
- 工具栏、右键菜单和快捷键入口；
- 当前可视标签页截图后自由笔、荧光笔、椭圆圈选和矩形标记；
- 保存选中文字、URL、标题、前后文、DOM Range、矩形与采集时页面正文哈希；
- 即时想法/TODO；
- 浏览器私有待同步箱与自动重试；
- 默认只持有 `activeTab` 和本机服务地址权限；其他服务 Origin 由用户单独授权。

浏览器内部页、扩展商店和策略禁止页面不能注入或截图时，扩展必须失败并说明，不能要求静默永久读取全部网站。

### 3.4 Capture Server 与 AI

必须具备：

- Python 可复现部署；
- SQLite 元数据、FTS5 全文搜索和内容寻址图片；
- 写入、第一方读取、AI 读取三个不同 Bearer Token；
- 创建/幂等重试、列表、读取、搜索、增量变更、软删除、恢复、彻底删除和 ZIP 导出；
- Web Inbox；
- AI 读取前执行每条记录的 `ai_access` 过滤；
- MCP 只注册搜索、单条读取、最近记录、TODO 和时间线五个只读工具；
- AI 调用审计不复制正文；
- 网页、OCR 和来源正文始终作为不可信证据，不能改变工具权限。

## 4. 记录主体必须分开

每条记录至少区分：

- `comment`：用户自己写下的想法；
- `source.text`：来源应用直接交付的原文；
- `ocr`：机器从图片推导的文字；
- `annotations`：用户在图片上留下的矢量标记；
- `assets.original`：未批注原图；
- `assets.annotated`：便于查看的批注图；
- `ai_access`：这条记录是否允许 AI 读取。

界面、搜索结果和 AI 回答不得把来源原文或 OCR 冒充成用户观点。AI 回答应引用记录 ID 和采集时间。

## 5. 权限与安全边界

- Android 辅助功能权限只能用于用户主动触发的一次截图。服务声明 `canRetrieveWindowContent=false`，运行时不订阅或处理 UI 内容。
- Windows 只使用公开桌面截图 API，不注入其他进程，不提权。
- 浏览器只在用户点击、右键或快捷键后读取当前标签页。
- Token 不进入源码、截图记录、普通日志或导出内容；Android Token 使用系统密钥加密，浏览器 Token 位于扩展私有存储，Windows Token 位于用户私有配置文件。
- 服务默认监听 `127.0.0.1`。跨机器使用应放在 TLS 反向代理后；明文 HTTP 只允许用户明确配置的回环或私有局域网地址。
- 银行、密码管理器、DRM 视频、Android `FLAG_SECURE`、Windows UAC 安全桌面、企业策略和系统保护页面可能返回拒绝、空白或黑色。V1 不提供任何绕过路径。

## 6. 本次明确不承诺

- macOS、Linux 桌面客户端或 iPhone/iPad 全局截图；
- 在第三方应用原界面内永久高亮；
- 后台持续监控屏幕、剪贴板、浏览历史、按键或 UI 树；
- 所有应用的精确文字；
- Windows UIA 选区；
- 手机上的桌面浏览器扩展；
- 端到端加密、多用户团队权限或零知识服务端；
- 附件分块断点续传；
- 自动语义分类、知识图谱或 AI 写入笔记；
- 未经用户确认的长期人格结论；
- 对受保护内容的截图成功保证。

## 7. 发布门槛

发布包至少包含：

1. 已签名 Android 测试 APK；
2. Windows 11 x64 便携 EXE；
3. Chrome/Edge 扩展 ZIP；
4. Capture Server/MCP 源码包；
5. 产品、权限、数据、API、安装、已知限制和验收文档；
6. 每个制品的 SHA-256；
7. 对应 Git 提交、分支和发布标签；
8. 自动构建与测试结果；
9. 未做实机验证的项目明确标为“待实机验收”，不能写成通过。

## 8. Core 验收用例

| ID | 操作 | 通过条件 |
| --- | --- | --- |
| CORE-AND-01 | Android 普通应用中点磁贴 | 出现一次系统允许的当前画面，触发页本身不成为主要内容 |
| CORE-AND-02 | 裁剪、划线、评论、保存后重启 | 本地 Inbox 仍有原图、批注图、JSON，评论主体独立 |
| CORE-AND-03 | 在支持的编辑器选择“处理文字” | 保存系统直接交付的 Unicode 文字，不标为 OCR |
| CORE-AND-04 | 安全窗口截图 | 明确失败或得到系统允许的空白结果，不绕过 |
| CORE-WIN-01 | 五类普通 Windows 应用按快捷键 | 都可进入同一冻结/矩形选择流程 |
| CORE-WIN-02 | 双屏负坐标选择并批注 | 裁剪位置、图片尺寸与 JSON 坐标一致 |
| CORE-WIN-03 | Esc 取消 | Inbox 不新增正式文件 |
| CORE-WEB-01 | 网页选中文字并右键保存 | 原文、URL、前后文和锚点分别存在 |
| CORE-WEB-02 | 网页截图后画圈 | 原图和批注图可在统一 Inbox 打开 |
| CORE-OFFLINE-01 | 断网后保存再联网 | 本地立即成功，随后重试上传且不重复创建 |
| CORE-AI-01 | AI 与第一方 Token 读取同一关键词 | AI 只看到允许记录；拒绝记录不泄露 |
| CORE-AI-02 | 枚举 MCP 工具 | 只有五个只读工具，无写入、删除或外部执行工具 |
| CORE-DATA-01 | 导出 ZIP | JSON 和图片可用通用工具读取，哈希可复算 |

自动构建可以证明制品可生成，但 Android/Windows 的系统权限、真实多屏和受保护内容仍需相应真实设备完成最终人工验收。
