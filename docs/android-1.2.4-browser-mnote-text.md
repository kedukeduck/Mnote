# Mnote Android 1.2.4-test：复杂页面扫描与应用内文字摘录

包名 `com.codex.mnote`，versionCode `14`；沿用测试签名。先保存未完成的编辑，再覆盖安装，不要卸载。账号、已有记录及在线服务端不变。

## 两条实机诊断的含义

- Chrome：已经跳过过渡页并取得来源根节点，但扫描只走到 57 个节点就达到上限，尚未读到有效范围。之前时间预算为 180 毫秒，且每个节点都额外刷新；这不能证明 Chrome 没有选区，只能证明本次扫描未完成。
- Mnote：过渡页已识别，但旧规则仍拒绝把其他 Mnote 窗口当作来源，因此在进入文字扫描前退出。本版支持当前 Mnote 页面作为文字来源。

## 扫描优化

1. 快捷面板里的点击预查仍使用 180 毫秒预算；收起面板后的读取使用 1000 毫秒预算，不把第一次点击也变成长扫描。
2. 先查输入焦点和无障碍焦点中的精确选区。不会移动焦点、点击页面或修改选区。
3. 改为逐个获取子节点，不再因为单个父节点列出超过 256 个孩子就立即退出。每次最多检查 1024 个节点、发起 2048 次子节点查询。
4. Android 13+ 在这次主动请求开始时清空无障碍框架缓存；成功后，未选中子节点不再重复调用刷新。候选选区、焦点和根节点仍重新校验；旧系统或清缓存失败时继续逐节点刷新。不新增事件订阅、不保留选择历史、不读取剪贴板。
5. 增加耗时、刷新查询次数、缓存重置状态；区分“时间上限”“数量上限”和“扫描完成但没有有效选区”。诊断仍只在进程内存中，不含正文、链接、包名或窗口 ID，不写文件、不上传。

时间预算是发起下一次查询前检查的截止时间，不能中断系统正在执行的单次跨进程查询，实际耗时可能超过预算。达到上限或发现不同选区冲突时，不把先遇到的零碎片段当作完整选中文字保存，仍回退截图。

清缓存 API 依据：[Android API 33 AccessibilityService 变更](https://developer.android.com/sdk/api_diff/33/changes/android.accessibilityservice.AccessibilityService)。

## Mnote 内摘录

在 Mnote 当前记录详情或文字编辑页选中文字，再点快捷设置 **单次摘录**，可以打开新的文字摘录并写想法。文字扫描只读当前窗口；未找到选区时不向后搜索旧 Mnote 编辑页或其他应用的选中文字。已有悬浮截图草稿仍优先恢复，不覆盖草稿。密码、隐藏及系统标记敏感节点继续过滤。

## Chrome 的能力边界

本版针对已反馈的扫描上限优化，未承诺所有 Chrome 版本和网页都能通过当前接口提供选区。传统单节点选区、网页跨节点选区与浏览器自定义选择并不完全等价；例如 Chromium 的一个实现版本把传统选区属性与可编辑节点一起设置，不能把浏览器中的任何视觉高亮都当成已获得精确字符范围。参考 [Chromium 节点构建实现](https://chromium.googlesource.com/chromium/src/+/fdf06a6805313aaa0e9af15153f14ea82f502f94/content/public/android/java/src/org/chromium/content/browser/accessibility/AccessibilityNodeInfoBuilder.java)。

若新版显示“扫描完成”且有效范围仍为 0，请反馈 Chrome 版本、系统版本、选中的是网页正文还是输入框，以及新的完整诊断。可用来源应用的文字分享功能交给 Mnote；本版不读取旧剪贴板、不自动复制或拼接正文来猜测选区。
