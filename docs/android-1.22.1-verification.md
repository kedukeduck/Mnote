# Mnote Android 1.22.1-test 验证

日期：2026-10-21（Asia/Shanghai）。分支 `agent/transcript-connection-state`，功能提交 `68d8cd6`。

## 原因与修复范围

登录成功后会立即发起账号同步。旧版 `CaptureAccountSync.runRecords` 在整个远程同步周期持有账号锁，`VideoTranscriptClient` 取凭据也等待同一把锁；等待发生在网络超时开始之前。因此同步耗时较长时，解析页面可以一直停在初始连接提示。这是可由代码和锁竞争回归验证的缺陷；没有读取手机线程转储，不宣称排除了设备网络等其他原因。

只改安卓：一次 `SharedPreferences.getAll()` 快照保持账号、规范化服务器、作用域、有效期和加密凭据一致，校验账号绑定后解密，不再等待同步长锁。请求前后继续校验作用域，禁止 HTTP 和重定向。网络等待 30 秒上限，底层不可中断网络调用最多占用两个工作线程；页面另有 45 秒兜底。超时后的迟到回调不覆盖新请求，POST 沿用原幂等 UUID，不自动重提或误删重试共享的任务。
