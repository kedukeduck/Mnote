# Mnote Android 1.23.1-test · 后台提交修复验收

日期：2026-10-23（Asia/Shanghai）。分支 `agent/fix-transcript-background-resume`，基于 `9225df7`；功能修复提交 `883ca48`。稳定分支、既有版本和服务端数据没有被覆盖。

## 原因与修复

1. 旧代码只通过 WorkManager 提交本机队列，`KEEP` 会忽略运行中或正在结束时的新触发。新增应用级、非页面级的异步处理器，即时尝试提交；运行期间的新触发合并保留，完成后再处理一次，不阻塞保存。
2. 正常「服务器仍在解析」被返回成 `Result.retry()`，触发指数退避。现在正常等待和暂时网络异常都安排新的短间隔后续检查，工作本身返回成功；鉴权失败停止热循环，等待重新登录。保留 15 分钟周期兜底，任务文件依旧持久保存。
3. 新版使用独立 v2 工作名称，精确取消旧版同账号 v1 工作，避免修复被排在旧工作数小时退避之后。新触发采用 `APPEND_OR_REPLACE`；已有排队的后续检查会复用，不重复堆积计时工作。
4. 原来必须读完整个历史列表才能提交；历史失败直接退出，历史很多时会耗尽本轮预算。现在本机首次提交优先、已知服务器任务直接查询，历史每轮最多两页并保存分页位置。已尝试但结果未知的提交仍先确认历史，再使用相同持久编号恢复，不重复生成提交编号。
5. 原来按创建时间固定处理最早八个活动任务，会饿死后续任务。现在记录每任务处理时间、公平轮转，并给新提交、已有任务和不确定提交预留名额。明确额度不足的任务有一分钟冷却，避免短轮询反复 POST。
6. 勾选解析但未创建任务就返回时，增加明确确认；不能跳过授权和同意。任务页区分「已存本机」「正在提交」和「服务器已接收」，避免把本机入队等同于服务器开始转写。

调度策略参考 [Android WorkManager 唯一工作策略](https://developer.android.com/reference/androidx/work/ExistingWorkPolicy) 和 [工作请求、退避与执行约束](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)。15 秒是应用请求的后续检查最小延迟，不承诺系统会精确按秒执行；无网络、省电或强制停止仍可能延迟本机提交和通知。
