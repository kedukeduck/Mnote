# Mnote Android 1.0.3-test：原地悬浮批注与来源页面链接

- 版本：`1.0.3-test`，versionCode `4`
- 包名：`com.codex.mnote`
- 发布标识：`mnote-android-v1.0.3-test`
- 基于用户已确认可用的 1.0.2-test；保持相同测试签名，可覆盖安装。

## 交付内容

### 原地悬浮批注

“单次摘录”仍等待快捷面板收起后进行一次截图，然后由已连接的无障碍服务显示 `TYPE_ACCESSIBILITY_OVERLAY` 编辑窗口，不再正常启动新的编辑 Activity。来源 App 在窗口下方；批注作用于这次冻结的截图，不会修改或操作来源 App 的真实页面。

保留圈选、画笔、荧光笔、撤销、分类、想法输入和原始裁剪 / 批注图片分开保存。顶部“收起”移除窗口，但保留当前会话；再次点“单次摘录”恢复同一截图、笔迹、文字与链接，不进行二次截图。快捷按钮在有未完成会话时显示“继续批注”。

关闭前需要确认；保存成功后关闭悬浮层并清除临时全屏草稿。服务中断、锁屏时收起窗口；服务销毁时释放窗口。已开始的原子保存允许完成，不提前删除它正在使用的草稿。

悬浮会话目前是**内存中的临时会话，不是可跨进程恢复的已保存草稿**。关闭无障碍服务、系统杀死进程或重启手机会使未保存的会话丢失，因此完成后务必点击保存。锁屏收起后的会话也依赖该进程仍存活。

如果设备在首次创建时拒绝悬浮窗口，会提示并退回原编辑页，保留同一张截图；不会为了保持“悬浮”外观而丢弃已采集内容。小屏幕、键盘占位下，下方输入区域可以滚动。

“随手记”仍是独立的纯文字入口，无需无障碍权限。通过快捷按钮打开随手记时，现有截图悬浮窗口会先收起，不把截图混入新笔记。

### 保存来源页面链接

- 系统“分享给 Mnote”或“处理文字”带有唯一网页链接时，从提供的文字中提取并显示；原始来源文字不改变。
- 截图悬浮层、普通编辑页与随手记中均可展开“来源链接”，主动粘贴或输入。
- 默认不读取剪贴板，只在点击“粘贴”后读取。多个不同链接时不猜选哪个，请用户手动选择原页面链接。
- 只接受合法 HTTP / HTTPS 网页链接，不执行 `intent:`、脚本、文件或任意自定义协议；保留原有查询参数与片段，不后台解析短链或访问目标网站。
- 在本机记录详情中点击“打开来源页面”，以普通浏览器 / App Link 方式打开。无法打开时可复制链接，不退而假装“打开 App 首页”就是回到了原页面。
- URL 与截图、评论、来源文字一同保存并同步，遵循记录原来的 AI 可见性策略。移除链接后保存不会再附带该链接。

### 微博使用示例

1. 在原帖页面下拉快捷设置，点击“单次摘录”，圈选截图并写想法。
2. 若尚未复制原帖链接，点击“收起”，在微博使用该动态自身的分享 / 复制链接操作。
3. 再次点击“单次摘录”，回到同一条尚未保存的批注。
4. 展开“来源链接”并点击“粘贴”，检查确实是这条动态的链接，再保存。
5. 在 Mnote 的记录详情点击“打开来源页面”。

**不能保证在任意第三方 App 截图时自动获得当前页面 URL。** 本版不读取其他应用的 UI 树、不会监听导航，也不通过截图识别文字猜测地址。微博等 App 的网页链接是否直接唤起原 App，取决于对应 App 的链接支持、设备默认设置和登录状态；内容删除、权限变化或原链接失效时也可能无法重返原帖。截图保留当时画面，URL 打开的是来源当前提供的页面，不是历史快照或精确滚动位置。

## 数据与兼容

- Android 本地记录增加可选 `sourceUrl` 与 `sourceUrlOrigin`（`shared_text` / `user_entered`）。
- 旧记录缺少这两个字段时按空值读取；现有图片、评论、分类与同步配置不迁移、不清除。
- Android 上传映射到现有协议的 `source.url` / `source.url_origin`。服务端已有 URL 保留与搜索能力，网页详情已有链接展示；本次没有修改或部署服务端运行代码，仅增加协议回归测试。
- 没有新增 `SYSTEM_ALERT_WINDOW` 权限；继续使用用户主动启用的无障碍服务。仍设置 `canRetrieveWindowContent=false`，运行时不订阅无障碍事件。
