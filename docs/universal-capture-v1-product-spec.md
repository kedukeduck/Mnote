# 个人知识库全局摘录完整目标规格

- 文档状态：完整产品目标与路线图；不是本次制品的已实现声明
- 更新日期：2026-08-30
- 首发平台：Windows 11、Android 11 及以上
- 目标读者：产品、设计、客户端、服务端、测试与交付人员

> 本次可以交付和验收的实现范围以 [V1 Core 交付契约](v1-core-release-contract.md) 为准。本文保留完整知识库目标，用于后续版本拆解；本文出现的功能只有在交付契约和验收证据同时标为通过时，才可对外声称已经实现。

## 1. 产品定义

个人知识库全局摘录 V1 是一套本地优先的个人采集、整理与 AI 检索系统。它首先解决的不是“把所有应用都变成可编辑的笔记页面”，而是：当内容出现在任意普通电脑或手机应用中时，用户可以主动冻结当前画面，圈选或划线，补充评论、灵感或 TODO，并把原始证据与自己的表达一起保存。

V1 的产品承诺是：

> 在 Windows 11 和 Android 11+ 上，任何能正常显示且操作系统允许捕获的普通应用，都可以通过系统级截图路径形成一条 L2 摘录；当来源应用主动暴露文本或安装了受支持的集成时，系统进一步保存 L3/L4 精确文本。

“任意应用”不等于绕过操作系统或来源应用的安全保护。银行、密码、DRM、企业策略、安全桌面等受保护画面可能无法捕获；系统必须解释限制，不能尝试规避。

## 2. 目标与成功标准

### 2.1 V1 目标

1. 用户在任意可捕获应用中，可以通过全局入口完成“触发、圈选/划线、评论、保存”。
2. 截图、OCR、精确文本、来源元数据与用户评论分别保存，不能混为一段不可追溯的文本。
3. 采集不依赖网络；联网后再同步、索引和供其他设备读取。
4. Windows 与 Android 的记录进入同一 Inbox、搜索与回顾空间。
5. AI 只能通过受控的只读接口检索，并必须引用记录和原始证据。
6. 用户能导出全部资料，也能彻底删除正文、附件、OCR、索引与衍生数据。

### 2.2 成功闭环

```text
看到内容
  -> 主动触发全局摘录
  -> 冻结画面并圈选/划线
  -> 写一句评论，或标为想法/TODO
  -> 本地立即保存
  -> 后台 OCR、来源增强与同步
  -> 在 Inbox、搜索和 AI 对话中带证据回看
```

### 2.3 产品指标

- 普通捕获场景中，从系统入口触发到出现可操作冻结画面的 P95：Windows 不超过 1.2 秒，Android 不超过 1.8 秒；最终阈值以验收设备为准。
- 用户在不整理文件夹和标签的情况下，可以在 5 秒内完成一次“圈选并保存”；该指标不包含用户书写评论的时间。
- 离线保存成功率 100%；进程被系统结束后，已确认保存的记录不能丢失。
- 任意检索结果都能区分原始内容、OCR、用户表达与 AI 生成内容。
- AI 返回的事实性结论必须能定位到至少一条用户有权访问的记录。

## 3. 范围与非范围

### 3.1 V1 必须交付

- Windows 11 常驻摘录客户端：全局快捷键、屏幕/窗口/区域捕获、圈选、划线、裁剪、遮挡、评论和离线保存。
- Android 11+ 采集端：快捷设置磁贴、应用内入口、可选悬浮入口、单次截图、批注、评论、离线保存，以及系统分享/“处理文字”入口。
- Chrome/Edge 桌面浏览器扩展：在用户主动调用时提供 L4 网页选区、URL、标题、上下文与锚点。
- Inbox 与搜索界面：查看、编辑自己的评论、转成 TODO、筛选、归档和删除。
- OCR 与索引：至少支持中文和英文，保存文字坐标与置信度。
- 跨端同步服务：记录、附件、变更与删除标记可靠同步；冲突不得静默覆盖。
- AI 只读接口：提供搜索、记录读取、近期想法、当前 TODO、确认记忆与时间线读取能力。
- 数据导出、加密备份、回收站、彻底删除和 AI 读取审计。
- 安装包、校验值、安装说明、权限说明、已知限制与验收报告。

### 3.2 V1 明确不做

- macOS、Linux、iPhone/iPad 的同等级全局捕获。
- 绕过 `FLAG_SECURE`、DRM、UAC 安全桌面、企业管理策略或其他系统保护。
- 在第三方应用内部永久绘制、修改或恢复高亮。
- 持续录屏、后台监控屏幕、定时偷取界面或按键记录。
- 完整 Notion 式多人编辑器、无限画布、知识图谱可视化与团队协作。
- AI 自动修改笔记、完成任务、删除资料、执行外部操作或自动形成敏感人格结论。
- 承诺所有来源都能产生精确文本；L2 是全局保底，L3/L4 是条件能力。

## 4. 内容保真等级

每条摘录都必须显示其最高已验证保真等级。等级描述的是“来源证据强度”，不是记录的重要性。

| 等级 | 名称 | 必备证据 | 典型来源 | 能否称为精确文本 |
| --- | --- | --- | --- | --- |
| L2 | 像素摘录 | 原始截图裁剪、坐标、批注层；OCR 为衍生数据 | 任意可捕获普通应用 | 否 |
| L3 | 来源暴露文本 | 来源应用或系统接口直接交付的选中文字、来源应用身份、采集时间 | Windows UI Automation、Android `ACTION_PROCESS_TEXT`/分享 | 是，但通常不能稳定复定位 |
| L4 | 可复定位来源摘录 | L3 全部证据，加 URL/文档 ID、来源快照或哈希、文字引用锚点与上下文 | Chrome/Edge 扩展、受支持的文档连接器 | 是，并可在相同来源版本中复定位 |

规则：

1. OCR 结果无论多准确都只能附属于 L2，不得标记为 L3。
2. 来源只提供文本但没有稳定 URL、文档 ID 或锚点时，最高只能是 L3。
3. L4 必须实际校验锚点；仅保存一个网页 URL 不构成 L4。
4. 同一记录可以同时拥有 L2 截图和 L3/L4 文本；界面应优先展示最强证据，但保留截图。
5. 获取精确文本失败时，保存 L2 并记录明确的降级原因，不能悄悄丢失采集。
6. 动态网页、登录态页面或内容变更导致 L4 锚点失效时，保留采集时快照与原等级，并显示“当前来源无法复定位”。

## 5. 主要使用场景

### 5.1 Windows 任意应用截图摘录（L2）

1. 用户在目标应用中按可配置全局快捷键。
2. 系统冻结当前可捕获画面；多显示器时保留正确的显示器、DPI 与坐标映射。
3. 用户选择矩形、窗口、全屏或自由形区域。
4. 用户可使用荧光笔、自由笔、矩形、椭圆、箭头、撤销/重做与马赛克/实色遮挡。
5. 用户输入“这让我想到什么？”，可选择 `摘录`、`想法` 或 `TODO`。
6. 本地事务完成后立即显示“已保存”；OCR、索引和同步异步执行。
7. 系统尝试读取前台应用、窗口标题与 L3 精确选区；失败不阻断 L2 保存。

### 5.2 Windows 精确选中文字（L3）

1. 用户先在来源应用中选择文字，再触发摘录。
2. 客户端只在该次用户动作后的短时窗口内查询前台控件。
3. 若控件实现 UI Automation `TextPattern`/`TextPattern2` 并提供非空选区，保存接口直接返回的 Unicode 文本、来源进程和窗口信息。
4. 截图路径仍然可用；用户可选择同时保留截图证据。
5. 若来源没有暴露选区，明确提示“此应用未提供精确文本，已按截图保存”。

Windows UI Automation 的 `GetSelection` 只能读取实现了相应文本模式的控件；来源不支持选择时可能返回空范围。因此 L3 不能作为“任意应用”的承诺。参考：[Microsoft UI Automation TextPattern](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.textpattern)。

### 5.3 桌面网页选区（L4）

1. 用户选中文字并调用扩展快捷键或右键菜单。
2. 扩展在一次明确用户手势后读取当前标签页。
3. 保存精确文字、URL、规范化 URL、标题、选区前后文、文字引用锚点、文字位置锚点、DOM 辅助路径、页面版本哈希与可见区域截图。
4. 保存前对锚点执行一次本页回放校验；不通过时降级为 L3 或 L2并标注原因。
5. 扩展默认使用临时 `activeTab` 权限，不要求永久读取全部网站。`chrome://`、扩展页、受策略限制页面等可能无法注入脚本。

### 5.4 Android 任意应用截图摘录（L2）

1. 用户点击快捷设置磁贴、应用内入口或已明确启用的悬浮按钮。
2. 系统进行一次截图；Android 11+ 可在用户启用辅助功能服务后调用系统截图能力。
3. 截图成功后打开全屏批注页；触发按钮本身不应出现在最终证据中。
4. 用户圈选、划线、裁剪、遮挡并写评论。
5. 内容先写入本机；断网时进入待同步队列。
6. 遇到安全窗口、系统拒绝或短时间频率限制时，显示具体、可操作但不诱导绕过的提示。

Android 的辅助功能截图 API 从 API 30 起提供，且服务必须声明截图能力；这不改变来源应用可以通过安全窗口禁止截图的事实。参考：[Android AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)。

### 5.5 Android 精确文本（L3/L4 条件路径）

- 用户在支持标准文字选择的应用中选择“处理文字”或“分享”到本应用时，直接保存系统 Intent 交付的 `CharSequence`，形成 L3；不得再用 OCR 替换它。
- 若分享载荷同时提供可靠 URL，系统成功取得并冻结来源版本，并能用文字引用锚点唯一复定位，则可升级为 L4。
- URL 缺失、页面需要登录、网络不可达、文字在页面中不唯一或快照校验失败时维持 L3；不能猜测 URL 或伪造 L4。
- Android Chrome 不支持安装桌面 Chrome 扩展，因此 V1 不承诺每个手机网页都能达到 L4。

`ACTION_PROCESS_TEXT` 由来源应用决定是否提供，输入文字位于 `EXTRA_PROCESS_TEXT`；并非所有应用或所有控件都会显示该入口。参考：[Android Intent ACTION_PROCESS_TEXT](https://developer.android.com/reference/android/content/Intent#ACTION_PROCESS_TEXT)。

### 5.6 快速记录

- Windows 全局快捷键和 Android 桌面快捷方式应提供“只记想法”入口，不要求先截图。
- 默认进入 Inbox，用户无需在采集时选择文件夹或标签。
- 快速记录可直接设为 TODO；任务必须是独立对象，并保留它由哪条记录触发。

### 5.7 搜索、回顾与 AI 交流

- 统一搜索覆盖用户评论、L3/L4 精确文本、OCR、来源标题、URL 和 TODO。
- 结果卡明确标注字段来源与保真等级。
- AI 回答应返回记录 ID、采集时间、来源与引用片段；用户可以一键打开原始证据。
- AI 只能读取用户授权范围，不能调用采集、编辑、删除、完成任务或外部执行接口。

## 6. 信息架构

V1 主导航只保留以下入口：

- `快速记录`：无截图的即时想法。
- `全局摘录`：系统触发后的截图或精确文本工作流。
- `Inbox`：尚未归档、尚未转成行动或需要补充来源的记录。
- `思考`：用户自己的评论、观点、问题与笔记。
- `行动`：今日、待办、等待中与已完成。
- `搜索`：全文、OCR、来源、日期、应用、等级和类型筛选。
- `AI 对话`：限定时间、项目或全库范围的证据式问答。
- `AI 对我的理解`：只显示用户已确认或待用户审核的记忆候选；V1 AI 接口只返回已确认项。
- `设置与隐私`：权限、排除应用、AI 可见性、同步、导出、审计与删除。

## 7. 功能需求

### 7.1 捕获与批注

- `CAP-001`：Windows 支持可配置全局快捷键，快捷键冲突时必须允许修改。
- `CAP-002`：Android 提供快捷设置磁贴与应用内入口；悬浮按钮是可选权限、默认关闭。
- `CAP-003`：L2 支持矩形、自由形、窗口与全屏截取；平台不支持某种形态时要在交付说明中明确。
- `CAP-004`：批注至少包含自由笔、荧光笔、矩形、椭圆、箭头、遮挡、撤销、重做与裁剪。
- `CAP-005`：保存原始裁剪、有限上下文图、矢量批注层和渲染预览；不得只保存压平后的最终图片。
- `CAP-006`：取消采集后不产生正式记录，并清理临时全屏素材。
- `CAP-007`：保存按钮必须以本地事务提交成功为准，不能把“已加入内存队列”显示成“已保存”。
- `CAP-008`：捕获失败必须返回稳定错误码、用户可读原因和允许的降级路径。

### 7.2 来源与保真

- `SRC-001`：保存采集时间、设备、平台、来源应用包名/进程、窗口标题（可取得时）和获取方式。
- `SRC-002`：L2 OCR 必须保存块级文字、坐标、语言、置信度与 OCR 引擎版本。
- `SRC-003`：L3 保存来源直接交付的原始 Unicode 文本、接入方法与选区数量。
- `SRC-004`：L4 至少保存文字引用锚点、来源 URI/文档 ID、来源版本或快照哈希和锚点校验状态。
- `SRC-005`：界面和 API 都必须返回实际等级与降级原因。
- `SRC-006`：用户评论必须与来源文字分字段、分主体保存。

### 7.3 记录、任务与版本

- `REC-001`：记录类型为 `capture`、`thought`、`task_source` 或 `journal`；类型可更改且保留修订。
- `REC-002`：记录支持归档、加星、项目/领域、标签和用户可见性，但采集时都不是必填。
- `REC-003`：TODO 是独立任务，包含状态、截止时间、来源记录与完成时间。
- `REC-004`：所有用户编辑产生修订号；同步冲突保留双方版本，不能最后写入者静默覆盖。
- `REC-005`：回收站默认保留 30 天；用户可立即彻底删除。

### 7.4 本地优先、同步与搜索

- `SYN-001`：无网络时可完成捕获、评论、查看本地记录、OCR（设备支持时）和搜索已建索引。
- `SYN-002`：附件上传可断点续传并以 SHA-256 校验；重复附件允许内容寻址去重。
- `SYN-003`：删除使用墓碑同步到所有设备，所有设备确认后再按保留策略物理清理。
- `SYN-004`：同步状态可见：仅本地、待同步、同步中、已同步、冲突、失败。
- `SEA-001`：关键词搜索必须覆盖用户文本、精确文本和 OCR，并允许单独关闭 OCR 命中。
- `SEA-002`：搜索支持时间、来源应用、记录类型、保真等级、项目和 AI 可见性筛选。

### 7.5 AI 只读

- `AI-001`：AI 使用独立只读凭证；服务端拒绝该凭证对任何写接口的调用。
- `AI-002`：AI 可调用的工具仅限搜索、读取记录、读取近期想法、读取任务、读取已确认记忆和读取时间线。
- `AI-003`：每次读取记录审计时间、调用方、查询、返回记录 ID 与发出的字段；不在普通日志中复制敏感正文。
- `AI-004`：网页、文档和 OCR 均视为不可信数据；其中的命令不能改变工具权限或触发写入。
- `AI-005`：AI 建议只能作为对话文本或结构化候选返回，由用户在第一方客户端确认；V1 MCP/API 不提供写入工具。

## 8. 系统构成

```text
Windows 捕获客户端 ----\
                       +--> 本地记录库/待同步队列 --> 个人同步与搜索服务
Android 捕获客户端 ----/                              |
Chrome/Edge 扩展 --> Windows 原生桥接                 +--> Web/桌面 Inbox
                                                      +--> 只读 MCP/API --> AI
```

边界要求：

- 捕获客户端负责用户触发、临时画面、批注和本地事务。
- 浏览器扩展只在用户动作后读取当前页，通过受认证的本机桥接提交，不监听浏览历史。
- 同步服务负责多设备一致性、附件、索引、授权、审计和删除传播。
- AI 网关不与第一方写接口共用凭证，返回数据前执行记录级与字段级权限过滤。

## 9. 降级策略

| 条件 | 允许行为 | 禁止行为 |
| --- | --- | --- |
| Android 未启用辅助功能 | 提供系统截图后分享、精确文本分享和应用内导入 | 反复弹窗强迫授权 |
| Android 安全窗口 | 显示“来源禁止截图”，允许只记想法 | 绕过 `FLAG_SECURE` 或录屏取帧 |
| Windows UIA 无选区 | 保存 L2 并标注 `source_text_unavailable` | 用 OCR 文本标成 L3 |
| 浏览器脚本不可注入 | 使用可见截图或用户分享的 URL | 请求永久全站权限作为静默兜底 |
| L4 锚点不唯一/失效 | 保留 L3/L2与快照，显示原因 | 随机选择一个匹配位置 |
| 网络或服务不可用 | 本地保存并排队 | 阻止采集或丢弃附件 |
| OCR 不可用 | 保存截图，状态显示待处理 | 把空 OCR 当成没有文字 |

## 10. 交付物

一次可交付的 V1 发布必须同时包含：

1. Windows 11 x64 安装包或明确标注的便携测试包，以及 SHA-256。
2. Android 11+ 测试 APK，以及 SHA-256、最低/目标系统版本和签名指纹。
3. Chrome/Edge Manifest V3 扩展包与安装说明。
4. 个人同步/搜索服务和只读 MCP 服务的可复现部署包。
5. Inbox/搜索/权限与审计界面。
6. 数据库迁移、备份、恢复与全量导出工具。
7. 本目录中的产品、权限隐私、数据 API 和验收文档。
8. 已知限制清单、自动化测试结果、人工验收证据与回滚说明。
9. 源代码对应的 Git 提交与发布标签；密钥、口令和个人数据不得进入仓库。

只有 Android APK、只有截图功能、只有设计稿或只有服务端均不构成本文定义的完整 V1。

## 11. 后续版本候选

- macOS 系统级捕获与 Safari 扩展。
- iOS/iPadOS 分享扩展，但不承诺跨 App 全局冻结画面。
- 支持 PDF、Office、电子书等来源的专用 L4 连接器。
- 端侧语义检索、端到端加密同步与零知识服务端模式。
- 经用户逐条确认的 AI 写入提案队列。
- 每日、每周、每月回顾与可验证的小实验闭环。

这些候选不改变 V1 的验收边界，也不得以“未来会做”为理由省略当前必需能力。
