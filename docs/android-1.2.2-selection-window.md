# Mnote Android 1.2.2-test：修复文字读取时的过渡窗口遮挡

包名 `com.codex.mnote`，versionCode `12`；沿用测试签名。保存未完成的编辑后覆盖安装，不要卸载；账号、记录与在线服务端不变。

## 修复内容

1.2.1 的第二次选区读取仍发生在全屏透明 Activity 上。透明背景只改变画面，不意味着底下应用仍是可交互窗口；Android 的无障碍窗口列表仅返回可交互窗口。因此，即使视觉上能看到原应用，也可能只读到 Mnote 的过渡窗口。

本版将等待快捷面板收起的过渡窗口缩为 1×1 像素，设置 `FLAG_NOT_TOUCHABLE | FLAG_NOT_TOUCH_MODAL`，去掉它占用整个屏幕交互区域的行为。保持可获取焦点，继续等待快捷面板收起后读取；仍使用独立无关联任务，不把 Mnote 首页带到来源应用前面。设置与错误提示使用独立的可交互对话框。

这修复了代码中明确存在的窗口配置问题，但没有用户手机的运行证据，不能断言它是所有失败的唯一原因。来源应用未暴露选区、切换焦点时取消选区、系统未授予内容读取能力或扫描预算不足仍可能导致截图回退。

官方依据：[AccessibilityService.getWindows](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#getWindows())；[Android 窗口过滤实现](https://android.googlesource.com/platform/frameworks/base/+/d12ed5b17c2a12c99666ba73fcb4b7293e177170/services/core/java/com/android/server/wm/AccessibilityController.java)。

## 怎么验证

1. 在来源应用选中文字 → 拉下快捷设置 → 点击 **单次摘录**。
2. 读到选区则进入文字摘录，可以写想法并选择保留同一文字块；否则仍进入截图。
3. 若仍然截图，取消本次截图，打开 Mnote → **快捷按钮与截图设置** → **来源识别与无障碍设置**。
4. 将其中 **最近一次文字摘录诊断** 的内容，以及手机型号、系统版本和来源 App 名称反馈给开发者。

诊断区分无障碍未连接、无可读来源窗口、当前仅有系统 / Mnote 窗口、已读来源但没有有效选区、扫描达到上限及成功读取。显示应用窗口数、来源根节点数、检查节点数和有效范围数；计数是本次查询的检查次数，不是全文字符数或保存记录数。

## 隐私与验证边界

- 不增加后台监听、选区历史、剪贴板读取或权限；不改变现有单次采集与原文逐条勾选策略。
- 诊断仅保留最后一次结果和计数，存放进程内存，不含选中文字、原文、链接、应用包名或异常详情，不写入文件、不上传。清空进程后重置。
- 自动化新增“快捷面板时无选区，非模态过渡窗口后有选区”的窗口过滤模型、窗口尺寸与标志、设置对话框可交互，以及诊断内容不泄漏文字的回归用例。此前测试直接提供可读节点，未覆盖窗口遮挡；新增模型仍不替代真实系统窗口管理器或厂商手机验收。
