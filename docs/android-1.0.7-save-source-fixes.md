# Mnote Android 1.0.7-test：本地刷新、提示与来源设置

包名 `com.codex.mnote`，versionCode `8`。调试 / 测试签名，与上一版一致。请保存编辑中的内容后覆盖安装，不要卸载旧版。

## 修复

1. **截图与保存反馈分开**：截图得到临时图片且成功打开悬浮编辑时显示“截图已就绪，圈选后点下一步保存”，不谎称记录已经保存。悬浮保存成功 / 失败保留标准文本 Toast，另显示一个约 2.6 秒的服务持有提示条，避免依赖已关闭的编辑层。提示条不可点击、不获取焦点，锁屏 / 服务停止时清除，下一次截图前清除。厂商拒绝提示窗口时仍保留系统 Toast；不能保证手机系统永不抑制 Toast。
2. **本地记录即时刷新**：`CaptureStore.save` 完整写入后发送仅本应用可接收的变更广播。已经打开的首页也会重读列表，不依赖 Activity 重启、上传完成或网络。通知异常不回滚已成功写入的记录。手动“刷新”先刷新本机列表，再尝试远端拉取，未配置 Token 时也不会跳过本机刷新。
3. **来源识别配置与入口**：不再在服务连接时将事件类型清零，保留窗口状态 / 窗口列表两类事件与交互窗口 / View ID 标志。事件回调仍为空，不读取、缓存或保存事件正文 / 应用导航历史；来源包名和适配浏览器地址栏仍只在主动截图时查询。首页增加无需展开高级设置的“来源识别与无障碍设置”，按实际已连接服务的能力标志显示状态。

## 在手机上操作

- 打开 Mnote → **来源识别与无障碍设置** → **打开辅助功能设置**（以按钮实际文字为准）。优先进入“Mnote 单次摘录”服务详情，厂商不支持直达时退回系统辅助功能列表；入口可能位于“已下载的应用 / 已安装的服务”。
- **没有单独的“来源识别”或“查看屏幕内容”设置开关**。窗口内容能力是启用 Mnote 服务时声明并授权的，不应该要求你寻找不存在的独立开关。
- 如果诊断提示缺少能力或未连接，关闭并重新启用“Mnote 单次摘录”。若 Android 明确提示受限设置，按系统提示在 Mnote 应用信息中允许后再回来操作。
- 回到浏览器或目标应用重新摘录，不要在系统设置页测试来源。浏览器地址取决于其可读地址栏，微博等原生应用内部 URL 仍不保证自动获取。
- “能力已启用”只说明服务具备权限，不保证当前应用提供可读窗口。若仍无法识别，请反馈手机型号、Android 版本、目标应用与版本，以及该诊断页的状态文字；不需要提供 Token 或私密页面内容。

## 证据与边界

本地刷新缺少保存广播、截图成功分支缺少 Toast、运行时事件类型被设为 0 都已在旧代码中确认。无实机日志，不能把最后一项断言为所有手机“来源未知”的唯一原因。没有新增普通悬浮窗、使用情况访问或后台输入监听权限，没有修改 / 部署线上服务器。

验证包括：本机离线保存立即更新已打开首页、丢失广播后的本地刷新、写入完成后通知、通知失败不破坏保存、截图就绪提示、短暂提示条不抢触控 / 焦点并自动清理、锁屏与服务销毁、设置直达 / 厂商降级、能力诊断、只保留窗口事件且不读事件内容，以及既有截图 / IME / 云端拉取回归。
